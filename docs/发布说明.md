# 发布说明：npm、GitHub Release 与插件市场

> 本文是 `dsh-time-watchdog` 的**发布操作手册**，仓库内随包分发。
> 目标读者是维护者本人；普通用户看 [README](../README.md) 的「安装」一节即可。

---

## 0. 三条发布通道，各管一件事

| 通道 | 作用 | 谁会用 |
| --- | --- | --- |
| **npm** | 让 `dsh plugin add dsh-time-watchdog` 真的能装 | 所有用户 |
| **GitHub Release** | 提供稳定的 `.tgz` 下载地址与版本说明 | 离线 / 内网安装 |
| **awesome-dsh-plugin** | 让插件出现在 DSH 的「插件市场 → 发现」里 | 逛市场找插件的人 |

三者**互相独立**：npm 发了不等于市场能搜到；市场收录了不等于 npm 有新版本。
下节的顺序是「先 npm，再 Release，最后市场」——这个顺序不是强制的，但最省事：
市场条目本身不含版本号，它只是指向你的仓库，版本号由上游 CI 从 npm 读。

## 1. 发 npm

包名就是 `dsh-time-watchdog`（已确认未被占用）。
**`dsh-clock` 这个名字在 npm 上已被别人占用**（另一个 DSH 插件，作者 trk23），
所以本插件从 1.0.0 起统一改名为 `dsh-time-watchdog`，包名 / 插件 ID / HTTP 路径 /
存档文件名 / 投影 key 全部一致，只有用户可见的斜杠命令保留 `/clock` 与 `/set-time`。

### 1.1 发布前自检

```bash
cd "C:/Users/ThinkPad/Desktop/dsh test/dsh-time-watchdog/待提交"

node --test "tests/*.test.mjs" "tests/*.mjs"   # 必须 0 fail
node -e "console.log(require('./package.json').version)"   # 记住旧版本号
git status -sb
npm pack --dry-run                             # 看包内容
```

- [ ] 测试全绿
- [ ] `CHANGELOG.md` 顶部已写这次改动
- [ ] 版本号没被别人占：`npm view dsh-time-watchdog versions`
- [ ] `files` 白名单覆盖了新增目录（当前：`lib, src, cordis.patch.yml, README.md, CHANGELOG.md, LICENSE`）
- [ ] `package.json` 里 `dsh.bundle.patch` 存在（这是能被 `dsh plugin add` 装上的前提）

> **本机 npm 有个坑**：默认 cache 目录 `C:\Users\ThinkPad\AppData\Local\npm-cache`
> 在这台机器上写不进去，`npm whoami` 会报 `EPERM ... _cacache\tmp\...`。
> 换个 cache 目录即可，凭据仍然生效：
>
> ```bash
> export npm_config_cache="C:/Users/ThinkPad/Desktop/dsh test/临时脚本/_npmcache"
> npm whoami          # → aawef
> ```

### 1.2 提版本并发布

```bash
npm version patch --no-git-tag-version    # 或 minor / major
#   然后手动在 CHANGELOG.md 顶部写一节，Release 正文就是它

git add -A
git commit -m "chore(release): 1.0.1"
git tag -a v1.0.1 -m "v1.0.1 — 修了什么"
git push origin main && git push origin v1.0.1

npm publish                               # 无 scope 包，不需要 --access public
```

开了 2FA 的账号会报 `E403 Two-factor authentication ... required`，两种解法：

```bash
npm publish --otp=123456                  # A：验证器里的 6 位码
```

或 B：npmjs.com → Access Tokens → **Granular** → 选包 / Read and write /
**勾 "Bypass two-factor authentication"** → `npm config set //registry.npmjs.org/:_authToken=<token>`。

> **发布后不要立刻 `npm view` 验版本**。`npm publish` 打印 `+ dsh-time-watchdog@x.y.z`
> 只代表 registry 收下了 tarball；`dist-tags` / `versions` 是异步刷新的，
> 有 1–2 分钟窗口查到旧数字。等 3–5 分钟再人工查一次：
>
> ```bash
> npm view dsh-time-watchdog version --prefer-online
> curl -s https://registry.npmjs.org/dsh-time-watchdog | grep -o '"latest":"[^"]*"'
> ```
>
> 同一版本重发必然 `403 You cannot publish over the previously published versions`。

### 1.3 验证装得上

```bash
cd "$(mktemp -d)" && npm i dsh-time-watchdog@<新版本号> --prefer-online --no-audit --no-fund \
  && node -p "require('./node_modules/dsh-time-watchdog/package.json').version"
```

报 `notarget No matching version found` 通常是**本机缓存**没有这个版本，加
`--prefer-online` 或换干净的 `npm_config_cache` 重试，不是没发布成功。

## 2. GitHub Release（tag 一推，CI 自动建）

`.github/workflows/release.yml` 在 `push v*` 时做四件事：

1. 校验 tag 与 `package.json` 的 `version` 一致（不一致直接失败，防发错版本）
2. `node --check` 语法自检 + 检查 `dsh.bundle.patch` 存在
3. 从 `CHANGELOG.md` **文首那一节**（或标题含版本号的那一节）抽正文当 release notes
4. `npm pack` 出 tgz，重命名成 `dsh-time-watchdog.tgz`（不带版本号）附到 Release

于是有稳定下载地址：

```
https://github.com/aawef/dsh-time-watchdog/releases/latest/download/dsh-time-watchdog.tgz
```

CI 挂了要手动兜底：网页端 `releases/new` 选 tag → 正文粘 CHANGELOG 本节。
补发历史 tag：Actions → **Release** → *Run workflow* → 填 tag 名。

验证（别用未认证的 API，会 403 限流）：

```bash
git ls-remote --tags origin | tail -3
curl -sI https://github.com/aawef/dsh-time-watchdog/releases/latest | grep -i "^location"
```

## 3. 提交到插件市场（awesome-dsh-plugin）

### 3.1 它是什么

[`awesome-dsh-plugin/awesome-dsh-plugin`](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)
既是一份精选列表，**也是 DSH 的格式 1 插件市场索引**。DSH 0.2.1+ 的
「插件 → 发现 → 索引源」加下面这个地址即可搜到收录的插件：

```
https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json
```

（同内容的 GitHub Pages 副本 `https://awesome-dsh-plugin.com/index.json` 和
`https://dshmarket.com/index.json` 也能用，但 DSH 只给索引源 15 秒超时，
这两个副本在某些网络上会超时，所以官方推荐 jsdelivr 那个。）

### 3.2 提交方式：一个 PR，加**一个文件**

**不要**手工编辑它的 README——那两份 README 由 `data/plugins/*.yml` 自动生成。
投稿就是新增：

```
data/plugins/aawef__dsh-time-watchdog.yml
```

内容（本插件已经写好的版本见下）：

```yaml
url: https://github.com/aawef/dsh-time-watchdog
name: aawef/dsh-time-watchdog
category: notify
description:
  en: 'Turn timer for DSH: reports how long the current turn has been running, injects wrap-up prompts on a /set-time schedule, and shows run-time cards above the composer.'
  zh: 'DSH 本轮计时看门狗：读取本轮已运行时长，按 /set-time 排程向模型注入收尾提示词，并在输入框上方显示运行时长卡片。'
```

要点：

- **`description.en` 必填**，`zh` 可选（不写维护者会补）。带 `: ` 的英文必须加引号，
  否则 YAML 会当成嵌套键解析。
- `category` 可选值：`agi` `ui` `usage` `theme` `model` `identity` `session`
  `memory` `tools` `wsl` `browser` `vision` `voice` `docs` `skill` `workflow`
  `git` `notify` `dev` `security` `remote` `market` `fun`。
  本插件选 **`notify`**（它做的核心事是「到点提醒」），不是 `ui`。
- 一个 PR 最多 3 条条目；一个文件一个插件，所以不会和别人冲突。

### 3.3 收录门槛（CI 自动校验前两条）

| 要求 | 本插件现状 |
| --- | --- |
| `package.json` 声明 **`dsh.bundle`**（只有 `dsh.client` 不算，这是最常见的被拒原因） | ✅ `dsh.bundle.patch: ./cordis.patch.yml` |
| 仓库创建满 **1 天** | ⚠️ 需要建仓后等一天再提 |
| 仓库有真实可用的代码 | ✅ 6 个源文件 + 6 个测试文件 |
| 加了 [`dsh-plugin`](https://github.com/topics/dsh-plugin) topic | 需在仓库 Settings → Topics 里加 |
| 描述属实、不带营销词 | 描述里每个命令（`/set-time`）和工具（`clock_elapsed`）都真实存在 |
| 项目活跃维护 | ✅ |

> **1 天门槛的实操**：仓库年龄从**建仓那一刻**算，不是从 push 那一刻算。
> CI 会拒掉「提 PR 前几分钟才建好」的仓库。所以正确顺序是
> **建仓 → 推代码 → 隔一天 → 提 PR**，不用重复提交。

### 3.4 提 PR 的完整命令

```bash
# fork 之后克隆（或直接用 GitHub 网页在线编辑，改一个文件而已，网页更快）
git clone https://github.com/<你的fork>/awesome-dsh-plugin.git
cd awesome-dsh-plugin
git checkout -b add-dsh-time-watchdog

cat > data/plugins/aawef__dsh-time-watchdog.yml <<'YAML'
url: https://github.com/aawef/dsh-time-watchdog
name: aawef/dsh-time-watchdog
category: notify
description:
  en: 'Turn timer for DSH: reports how long the current turn has been running, injects wrap-up prompts on a /set-time schedule, and shows run-time cards above the composer.'
  zh: 'DSH 本轮计时看门狗：读取本轮已运行时长，按 /set-time 排程向模型注入收尾提示词，并在输入框上方显示运行时长卡片。'
YAML

git add data/plugins/aawef__dsh-time-watchdog.yml
git commit -m "Add aawef/dsh-time-watchdog"
git push origin add-dsh-time-watchdog
# 然后在 GitHub 上开 PR
```

PR 合并后 `main` 上自动重建两份 README，你不需要跑 `npm ci && node scripts/generate-readme.mjs`
（本地预览跑一下也行，提交结果同样被接受，只是必须与数据源一致）。

### 3.5 收录之后

- **日常发版不用碰那个仓库**：条目里只有 `url` / `name` / `category` / `description`，
  **没有版本号**。版本号由上游 CI 从 npm 读出来写进 `plugins.json`。
- **市场卡片上的版本号会滞后约一天**：`plugins.json` 是上游定期重建的快照
  （文首 `updated` 字段就是上次构建日期），不是「你一推就同步」。
  卡片滞后 ≠ 装到旧版，`dsh plugin add` 走 npm 拿的永远是最新版。
- 想改描述/换分类时才需要再提一个 PR 改那个 yml。
- 仓库消失 / 归档 / 长期停更会被周期性扫描标记，确认后移除；保持活跃即可。

### 3.6 被拒了怎么办

CI 通过只是**前置条件**，合并前维护者会实际读仓库。最常见的打回原因是：

1. 只声明了 `dsh.client`，没有 `dsh.bundle` → 补 `dsh.bundle.patch` + `cordis.patch.yml`
2. 仓库不满 1 天 → 等到满再提
3. 描述夸大（写了不存在的命令/工具/数量）→ 按代码改描述
4. 分类离得太远 → 一般维护者会直接改，不会打回

## 4. 发完之后：本机怎么用上新版

本机桌面端装的是 **`file:` 本地依赖**，不是从 npm 拉的：

```
profiles/desktop/package.json → "dsh-time-watchdog": "file:../web/my-plugins/dsh-time-watchdog"
```

`my-plugins/<id>` 是指向 `待提交/` 的 junction，`node_modules/<id>` 是 pnpm 装出来的**副本**（不是链接）。
所以：

- **改已有文件**：源目录一改，junction 立刻看到；但 pnpm 的副本不一定是硬链接，
  保险做法是改完 `pnpm install` 一次。
- **新增 / 删除文件**：必须 `pnpm install`（硬链接/副本管不到目录项）。
- **宿主侧 `lib/index.js` / `src/*` 改完必须重启桌面进程**（ESM 只在启动时加载）。
- **`lib/client.js` 改完刷新页面即可**（客户端资源 no-cache）。

```bash
cd ~/.dsh/profiles/desktop && pnpm install
# 然后重启 DeepSeek Harness 桌面进程
```

## 5. 常见坑速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `npm whoami` 报 `EPERM ... _cacache` | 本机默认 npm cache 目录写不进去 | `export npm_config_cache=<可写目录>` |
| `E403 ... previously published versions` | 版本号没改 | `npm version patch` |
| 发布成功但装下来缺文件 | `files` 白名单漏了目录 | 补白名单后**再提一个版本**（同版本不能补发） |
| 刚 publish 完 `npm view` 还是旧版本号 | registry 元数据异步刷新 | 别重发、别轮询，3–5 分钟后人工查一次 |
| `git push` 无输出、一直不返回 | Git 在等凭据提示 | Ctrl-C，改 `GIT_TERMINAL_PROMPT=0 git push ...` |
| 市场 PR 被 CI 拒：缺 manifest | 只有 `dsh.client` | 补 `dsh.bundle` + `cordis.patch.yml` |
| 市场 PR 被 CI 拒：仓库太新 | 建仓不满 1 天 | 等满一天重新提交 |
| 市场能搜到但版本号旧 | 上游 `plugins.json` 是周期快照 | 正常，约一天自动跟上 |
